### Задание 2

```cpp
char a = 'a';
a = a + 10;
std::cout << a;
a = a + 250;
std::cout << a;
```

Используем коды символов ASCII:

- `'a'` = 97 = `0b01100001`;
- `97 + 10 = 107`, а код 107 — это `'k'`;
- затем `107 + 250 = 357`.

В `char` длиной 1 байт значение хранится по модулю 2^8 = 256:

357 mod 256 = 101

Код 101 — символ `'e'`.

Поэтому программа выводит:

```text
ke
```

Первый символ появляется из обычного сложения кодов, а второй — после переполнения `char`.

### Задание 3

```python
a = 'a'
a = chr(ord(a) + 10)
print(a, end='')

a = chr(ord(a) + 250)
print(a, end='')
```

Результат:

```text
kť
```

Почему результат отличается от C++:

- в C++ `char` имеет фиксированную разрядность, поэтому после `357` происходит переполнение 8-битного значения: `357 mod 256 = 101`;
- в Python `int` имеет произвольную длину, поэтому значение `357` не переполняется;
- `chr(357)` возвращает Unicode-символ с кодом 357 — `ť`.

### Задание 4

Дана программа:

```cpp
unsigned short x = 40000;
unsigned short y = x + x;
unsigned short z = x * 2;
y = y - x;
z = z / 2;
std::cout << y << " " << z << std::endl;
```

Для 16-битного `unsigned short`: `2^16 = 65536`

Сначала:

`y = 40000 + 40000 = 80000`

После записи в `unsigned short`:

`80000 mod 65536 = 14464`

То же происходит с `z`:

`z = 40000 * 2 = 80000`,

поэтому `z = 14464`.

Дальше:

`y = 14464 - 40000 = -25536`

При записи результата обратно в `unsigned short`:

`-25536 mod 65536 = 40000`

А для `z`:

`z = 14464 / 2 = 7232`.

Итог: `40000 7232`

Почему `x + x - x = x`, но `(x * 2) / 2 != x`: при первом вычислении после переполнения снова получается `x`, потому что из результата `80000 mod 65536 = 14464` вычитается `40000`, после чего происходит ещё одно приведение по модулю. Во втором случае деление выполняется уже после потери старших разрядов, поэтому исходное значение восстановить нельзя.

### Задание 7

#### 1. `(1000 & 100) << 10`

В двоичной записи:

```
1000 = 1111101000
 100 = 0001100100
```

Побитовое `AND`:

```
1111101000
0001100100
----------
0001100000 = 96
```

Теперь:

`96 << 10 = 96 * 1024 = 98304`

Ответ:

```
98304
```

#### 2. `(1000 >> 4) & 15`

`1000 >> 4 = floor(1000 / 16) = 62`.

Так как `15 = 1111` в двоичной, операция `& 15` оставляет четыре младших бита:

`62 & 15 = 14`.

Ответ:

```
14
```

#### 3. `~1234 + 1234`

Для двоичного дополнительного кода:

`~x = -x - 1`.

Поэтому:

`~1234 + 1234 = (-1234 - 1) + 1234 = -1`.

Ответ:

```
-1
```

#### 4. `(1000 ^ 500) & 63`

В двоичном виде:

```
1000 = 1111101000
 500 = 0111110100
```

XOR:

```
1111101000
0111110100
----------
1000011100 = 540
```

`63 = 00111111` в двоичной, поэтому:

`540 & 63 = 28`.

Ответ:

```
28
```

#### 5. `(100 << 3) + (100 >> 3)`

`100 << 3 = 100 * 8 = 800`,

`100 >> 3 = floor(100 / 8) = 12`.

Следовательно:

`800 + 12 = 812`.

Ответ:

```
812
```

### Задание 9

Найти все значения знакового целого `x`, для которых:

```
x & (x - 1) = 0
```

Для положительного числа это происходит тогда и только тогда, когда в двоичной записи ровно одна единица. Поэтому:

`x = 2^k`.

Кроме того, подходит `x = 0`.

Для знакового `n`-битного целого есть ещё одно отрицательное значение:

`x = -2^(n - 1)`.

У него двоичный код имеет единственную единицу в старшем разряде. После вычитания единицы:

```
1000...000
0111...111
```

и

```
1000...000 & 0111...111 = 0
```

Для типичного 32-битного `int` все решения:

```
0,
1, 2, 4, 8, ..., 2^30,
-2^31
```

### Задание 10

Найти все `x`, для которых:

```
x | (2 * x) = 1975
```

Двоичная запись результата:

```
1975 = 11110110111
```

Так как результат положительный, отрицательные `x` не подходят: у отрицательного числа старшие биты единичны.

Поскольку `2*x` — это сдвиг `x` влево на один бит, операция объединяет единицы `x` с единицами того же числа, сдвинутыми на одну позицию.

```
  01x10010011
| 1x100100110
-------------
  11110110111
```

Где `x` — либо `0`, либо `1`.

Следовательно, ответы:

```
1010010011
1110010011
```

Проверка подходящих вариантов:

```
659 = 1010010011
2*659 = 10100100110

  01010010011
| 10100100110
--------------
  11110110111 = 1975
```

Второй вариант:

```
915 = 1110010011
2*915 = 11100100110

  01110010011
| 11100100110
--------------
  11110110111 = 1975
```

Других вариантов нет, поэтому:

```
x = 659 или x = 915
```

### Задание 11

Пусть младшая установленная единица числа `x` находится в позиции `k`. Тогда `x` имеет вид:

```
xxxx1000...000
```

где справа от этой единицы находятся `k` нулей.

В дополнительном коде:

`-x = ~x + 1`.

При инвертировании и добавлении единицы получается:

```
yyyy1000...000
```

причём все разряды ниже позиции `k` снова равны нулю, а в позиции `k` стоит единица.

При выполнении `x & -x` все старшие биты обнуляются, а остаётся только эта единица:

`x & (-x) = 2^k`.

То есть результат — **наименьшая степень двойки, входящая в разложение `x`**, или, иначе, число, соответствующее самой младшей установленной единице `x`.

После этого программа вычитает найденную степень двойки из `x` и повторяет процесс.

Для `x = 0` цикл вообще не выполняется.

### Задание 12

#### Можно ли сохранить более 8 чисел?

Нет.

Каждое число от 0 до 15 требует 4 бита:

`0...15` соответствует `0000...1111`.

В `unsigned int` длиной 32 бита помещается: `32 / 4 = 8` таких чисел. Для девятого числа места уже не останется. Разве что использовать тип большей длины.

#### Сколько чисел можно сохранить для диапазона 0–7?

Числа от 0 до 7 требуют 3 бита:

```
0 = 000
1 = 001
2 = 010
...
7 = 111
```

Поэтому:

`floor(32 / 3) = 10`.

Можно сохранить **10 чисел**, причём останутся 2 неиспользованных бита.

#### Зачем нужна константа 15?

```
15 = 1111
```

Операция `v & 15` оставляет только четыре младших бита. Это позволяет извлечь одно упакованное число.

#### Нужно ли заменить 15 на 10 для диапазона 0–10?

Нет.

Число 10 — это максимальное **значение**, а не маска количества бит:

```
10 = 1010
```

Если использовать `v & 10`, будут сохранены только отдельные биты, а не всё четырёхбитное число.

Для диапазона 0–10 по-прежнему нужно 4 бита, поэтому маска должна оставаться:

```
15 = 1111
```
