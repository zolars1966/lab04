### Задание 2

```cpp
char a = 'a';
a = a + 10;
std::cout << a;
a = a + 250;
std::cout << a;
```

Используем коды символов ASCII:

- `'a'` = 97 = `0b01100001`;
- `97 + 10 = 107`, а код 107 — это `'k'`;
- затем `107 + 250 = 357`.

В `char` длиной 1 байт значение хранится по модулю 2^8 = 256:

357 mod 256 = 101

Код 101 — символ `'e'`.

Поэтому программа выводит:

```text
ke
```

Первый символ появляется из обычного сложения кодов, а второй — после переполнения `char`.

### Задание 3

```python
a = 'a'
a = chr(ord(a) + 10)
print(a, end='')

a = chr(ord(a) + 250)
print(a, end='')
```

Результат:

```text
kť
```

Почему результат отличается от C++:

- в C++ `char` имеет фиксированную разрядность, поэтому после `357` происходит переполнение 8-битного значения: `357 mod 256 = 101`;
- в Python `int` имеет произвольную длину, поэтому значение `357` не переполняется;
- `chr(357)` возвращает Unicode-символ с кодом 357 — `ť`.

### Задание 4

Дана программа:

```cpp
unsigned short x = 40000;
unsigned short y = x + x;
unsigned short z = x * 2;
y = y - x;
z = z / 2;
std::cout << y << " " << z << std::endl;
```

Для 16-битного `unsigned short`: `2^16 = 65536`

Сначала:

`y = 40000 + 40000 = 80000`

После записи в `unsigned short`:

`80000 mod 65536 = 14464`

То же происходит с `z`:

`z = 40000 * 2 = 80000`,

поэтому `z = 14464`.

Дальше:

`y = 14464 - 40000 = -25536`

При записи результата обратно в `unsigned short`:

`-25536 mod 65536 = 40000`

А для `z`:

`z = 14464 / 2 = 7232`.

Итог: `40000 7232`

Почему `x + x - x = x`, но `(x * 2) / 2 != x`: при первом вычислении после переполнения снова получается `x`, потому что из результата `80000 mod 65536 = 14464` вычитается `40000`, после чего происходит ещё одно приведение по модулю. Во втором случае деление выполняется уже после потери старших разрядов, поэтому исходное значение восстановить нельзя.

### Задание 6

Нужно умножить число на 1000, используя только сдвиги и сложение, без циклов.

Разложим 1000 по степеням двойки: `1000 = 512 + 256 + 128 + 64 + 32 + 8` или `1000=2^9 + 2^8 + 2^7 + 2^6 + 2^5 + 2^3`

Поэтому:

```python
x = int(input())
y = (x << 9) + (x << 8) + (x << 7) + (x << 6) + (x << 5) + (x << 3)
print(y)
```

Каждый сдвиг влево на `k` эквивалентен умножению на `2^k`.

### Задание 7

#### 1. `(1000 & 100) << 10`

В двоичной записи:

```
1000 = 1111101000
 100 = 0001100100
```

Побитовое `AND`:

```
1111101000
0001100100
----------
0001100000 = 96
```

Теперь:

`96 << 10 = 96 * 1024 = 98304`

Ответ:

```
98304
```

#### 2. `(1000 >> 4) & 15`

`1000 >> 4 = floor(1000 / 16) = 62`.

Так как `15 = 1111` в двоичной, операция `& 15` оставляет четыре младших бита:

`62 & 15 = 14`.

Ответ:

```
14
```

#### 3. `~1234 + 1234`

Для двоичного дополнительного кода:

`~x = -x - 1`.

Поэтому:

`~1234 + 1234 = (-1234 - 1) + 1234 = -1`.

Ответ:

```
-1
```

#### 4. `(1000 ^ 500) & 63`

В двоичном виде:

```
1000 = 1111101000
 500 = 0111110100
```

XOR:

```
1111101000
0111110100
----------
1000011100 = 540
```

`63 = 00111111` в двоичной, поэтому:

`540 & 63 = 28`.

Ответ:

```
28
```

#### 5. `(100 << 3) + (100 >> 3)`

`100 << 3 = 100 * 8 = 800`,

`100 >> 3 = floor(100 / 8) = 12`.

Следовательно:

`800 + 12 = 812`.

Ответ:

```
812
```
